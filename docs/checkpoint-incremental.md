# 检查点等待优化实施记录

目标：同时缩短检查点发布与立即撤销的等待，保留当前事务、取消和恢复语义。

三个子任务：

- 增量快照：从完整 before 的私有 Git tree 更新受影响路径，复用其余对象，重新校验可见路径集合、忽略证明、对象闭包和拓扑，产出完整 after。
- 结算与维护：可信非空事件回退时直接捕获；有界展开目录的 before/current 路径并发布 pending；把缓存落盘与对象整理延迟到空闲期，前台操作可取消维护并等待其安全退出。
- 验证：目录创建/删除/重命名、忽略规则、仓库边界、事件失信、重启与历史树导航、立即 undo/redo，以及同机基准。

关键边界：事件表示路径曾变化，不保证内容最终不同；跳过 baseline 探测只改变成本。恢复计划按精确路径匹配，因此目录必须展开旧、新叶子及所需目录项。目录展开超限、Git/忽略配置变化、拓扑不一致、符号链接和不可信事件继续完整结算。

完整 after 在后台生成；检查点的保守 changedPaths 不变，避免扩张撤销范围。物化记录绑定原 checkpoint 的 checksum，并独立持久化，重启和历史导航可重新读取完整快照。旧 scoped/pending 历史继续按原路径处理。

只读子任务已复核 pending 的锁顺序、精确 scope 与完整 coverage 约束；实现会在物化等待后再获取撤销锁，并在发布完整 manifest 前核验其证明。
